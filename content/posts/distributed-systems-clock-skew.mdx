## Physical time is an estimate

Every server has a clock, but no two clocks agree perfectly. Network delay, oscillator drift, and virtual-machine scheduling make an observed timestamp an estimate rather than a fact.

> A distributed system should use wall-clock time for observation, not as the sole source of ordering.

## Keep causality explicit

NTP reduces error but cannot eliminate it. When an application needs a stable order across nodes, attach logical information to each event instead of relying on a timestamp alone.

<CodeSnippet language={"typescript"} filename={"hybrid-clock.ts"} code={"type HybridTimestamp = { wallTime: number; logical: number };\n\nfunction nextTimestamp(previous: HybridTimestamp): HybridTimestamp {\n  const wallTime = Date.now();\n  return wallTime > previous.wallTime\n    ? { wallTime, logical: 0 }\n    : { wallTime: previous.wallTime, logical: previous.logical + 1 };\n}"} />

<Callout tone={"tip"} title={"Gợi ý vận hành"}>
Theo dõi clock offset như một chỉ số hạ tầng. Cảnh báo sớm khi độ lệch vượt ngưỡng thay vì chờ nó biến thành lỗi thứ tự dữ liệu.
</Callout>

<Details summary={"Khi nào chỉ cần timestamp thông thường?"}>
Với dữ liệu chỉ phục vụ hiển thị hoặc log không cần suy luận quan hệ nhân quả, wall-clock time vẫn là lựa chọn đơn giản và phù hợp.
</Details>

## Operational rule

Measure clock offset, alert on large drift, and document the maximum tolerated skew. Hybrid logical clocks make causal order visible without pretending physical time is exact.
